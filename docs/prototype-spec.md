# 原型规格

> 对应文件：`prototype/index.html`（单文件页面）、`prototype/engine.js`（推演引擎）、`config/example-settings.json`（示例用户）、`tests/engine.test.js`（行为锁定）

这份文档让没有任何对话上下文的实现者能完整理解和重建原型：它是什么、引擎的精确规则、数据结构、测试向量和界面规格。新系统（见 [`prd.md`](prd.md)）以此为行为基准。

## 1. 原型是什么

- 一个约 70 KB 的单文件 HTML 页面，中文界面，纯前端；用 CDN 加载 Chart.js 4.4.1 画图，其余代码全部内联
- 推演引擎约 230 行，纯函数、无依赖，与 `prototype/engine.js` 相同（页面里是内联副本，仅少了末尾的 `module.exports`）
- 直接用浏览器打开 `prototype/index.html` 即可运行：默认显示示例用户；改动保存在浏览器本地存储；"计划设置"里可以导入一个设置 JSON（例如未入库的 `config/settings.json`）
- 原型最初托管在 claude.ai 上，那里使用平台提供的私有文档库保存设置（文档 `plan/settings` 存 `{settings, updatedAt}`）和月底记录（集合 `checkins`，文档 id 为 `YYYY-MM-DD`）；本地运行时没有这层存储，自动退回浏览器本地存储

## 2. 推演规则

引擎入口 `ENG.simulate(settings, start)`：输入设置和起点（月份 + 各账户余额），输出逐月记录和里程碑。分两层。

### 2.1 工资单 `payroll()`

总是从首个发薪日算起，与起点无关，以保证年内累计正确。

1. 发薪日 = `income.firstPaycheck` 起每 14 天一次；每年张数按实际日期计数
2. 每张税前 = base ÷ 26
3. 医疗保费 = `ded.premium`（每张工资单，税前扣除）
4. HSA：`ded.hsaEligible` 为真且月份 ≥ `ded.hdhpStart` 时扣；生效当年额度按 (13 − 起始月) ÷ 12 折算；每张 = 当年剩余额度 ÷ 当年剩余张数
5. 401(k)：比例和类型按年取 `k401` 中不晚于当年的最近一项；每次扣款不超过当年剩余额度 `limits.k401`
6. 联邦预扣 = 年化法：(税前 − 保费 − HSA − Traditional 401k) × 26 减标准扣除后按税档计算，再 ÷ 26
7. 加州预扣 = 同法，但 HSA 不能扣除；减去个人免税额抵免
8. FICA = (税前 − 保费 − HSA) × 7.65%，社保部分受年度工资上限约束；SDI = 同口径 × 1.3%
9. 到手 = 税前 − 保费 − HSA − 401k − 联邦 − 加州 − FICA − SDI
10. Variable：从 `income.firstVariable` 起每 3 个月发一次，每次 = 年额 ÷ 4，记在当月 15 日；同样扣 401(k)；预扣按法定补充税率（联邦 22%、加州 10.23%）+ FICA + SDI；不扣 HSA 和保费
11. 雇主 match：月份 ≥ `income.matchFrom` 时，设本次实际扣款比例为 p%，按 `income.match` 的分档累加：每档贡献 (min(p, upTo) − 上一档 upTo) × rate；结果乘以税前，直接进 401(k)
12. 退税：每年按全年应税工资算实际联邦和加州税负，与全年预扣之差在次年 3 月作为一笔现金流入（负数即补税）

### 2.2 逐月循环

从起点月份到 `plan.end`，每月按以下顺序：

1. 搬家判断：`move.mode` 为 month 且到了指定月份 → 已搬家
2. 当月收入 = 当月所有工资单到手 + variable 到手 + 退税
3. 当月开销：已搬家用 `exp.moved`；否则月份 ≥ `exp.improveFrom` 用 `exp.improved`；再否则用 `exp.now`。注册费在 `exp.regMonth` 月且月份晚于 `exp.regPaidThrough` 时加上
4. 利息：应急现金和 Roth IRA 内现金按 `plan.hysa` ÷ 12 计息
5. 债务：先按 `debt.rate` ÷ 12 计息，再扣月供 `debt.min`
6. 支票账户 += 收入 − 开销 − 月供；低于 `plan.buffer` 时从应急现金补足
7. 可分配额 = 支票账户 − `plan.buffer`，按瀑布依次分配：
    1. **债务**（月份 ≥ `debt.payoffStart` 且有余额）：先从应急现金中拿出超过 `debt.keepCash` 的部分还掉，再用可分配额还本金
    2. 债务还清后才进入以下各级
    3. **保底**：应急现金 < `plan.floorMonths` × 基准月开销时补到保底线
    4. **补存上一年 Roth IRA**（仅 1–4 月，`plan.rothPrior` 为真，且上一年有工资收入）：用可分配额填上一年剩余额度；4 月仍未填满时，从应急现金中超出保底线的部分补
    5. **第一个桶**：应急现金补到 `plan.b1Months` × 基准月开销
    6. **第二个桶**（尚未进入投资阶段时）：先存当年 Roth IRA（受剩余额度约束，放货币基金），再补应急现金，直到 应急现金 + Roth IRA 现金 ≥ `plan.b2Months` × 基准月开销
    7. **进入投资阶段**：两个桶首次都满的那个月，Roth IRA 现金全部转为投资
    8. **投资阶段**：应急现金保持在 max(第一个桶目标, 第二个桶目标 − Roth IRA 累计本金)；然后存满当年 Roth IRA（投资）；剩余进券商账户
8. 自动搬家：`move.mode` 为 auto 且两个桶都满 → 下个月起按搬家后开销
9. 增长：401(k)、HSA、Roth IRA 投资部分、券商按 (1 + `plan.ret`%)^(1/12) − 1 月度复利；401(k) 和 HSA 加上当月缴款与 match

### 2.3 关键定义

- 基准月开销 = `exp.moved` 合计（`plan.basis` 为 moved 时）或 `exp.improved` 合计
- 阶段：债务未清 → debt；第一个桶未满 → b1；第二个桶未满 → b2；否则 invest
- 里程碑记录首次达成的月份：债务还清、第一个桶满、第二个桶满、开始投资、搬家
- 非美元存款（字段 `foreign`）默认不参与；`plan.foreignCounts` 为真时计入应急现金的达标判断，但不会被花掉
- 起点来自月底记录时，起点月份 = 记录日期的下一个月；Roth IRA 余额全部视为现金，本金取记录里的 `rothPrin`

## 3. 数据结构

### 3.1 设置

金额单位为美元；月份为 `YYYY-MM`；日期为 `YYYY-MM-DD`。完整示例见 `config/example-settings.json`。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `income.base` | 数字 | Base 年薪 |
| `income.variable` | 数字 | Variable 年额，按季度均分 |
| `income.includeVariable` | 布尔 | 是否计入 variable |
| `income.firstVariable` | 月份 | 首次发放月份，之后每 3 个月 |
| `income.firstPaycheck` | 日期 | 首个发薪日，之后每 14 天 |
| `income.matchOn` / `matchFrom` | 布尔 / 月份 | 是否计入雇主 match、开始月份 |
| `income.match` | `[{upTo, rate}]` | match 分档，按 upTo 升序；如 `[{"upTo":3,"rate":1},{"upTo":5,"rate":0.5}]` 表示前 3% 全额、再 2% 配一半 |
| `ded.premium` | 数字 | 每张工资单的医疗保费（税前） |
| `ded.hsaEligible` | 布尔 | 医疗计划是否为 HDHP、可存 HSA |
| `ded.hdhpStart` | 月份 | HDHP 生效月 |
| `k401.<年份>` | `{pct, type}` | 该年起的 401(k) 比例与 `roth` / `trad`；未列出的年份沿用最近一项 |
| `limits.k401` / `hsa` / `roth` | 数字 | 年度额度 |
| `exp.now` / `improved` / `moved` | 对象 | 三个阶段的月开销，键为 `rent`、`util`、`carIns`、`gas`、`carMaint`、`subs`、`food`、`personal`、`irregular` |
| `exp.improveFrom` | 月份 | 从 now 切换到 improved 的月份 |
| `exp.reg` / `regMonth` / `regPaidThrough` | 数字 / 1–12 / 月份 | 年度车辆注册费、缴费月份、已缴到哪个月 |
| `move.mode` / `month` | `auto` / `month` / `never`，月份 | 搬家方式 |
| `debt.rate` / `min` | 数字 | 债务年利率 %、月供 |
| `debt.keepCash` | 数字 | 用存款一次性还债时的保留额 |
| `debt.payoffStart` | 月份 | 开始提前还款的月份 |
| `plan.buffer` | 数字 | 支票账户常留 |
| `plan.b1Months` / `b2Months` / `floorMonths` | 数字 | 两个桶和保底线的月数 |
| `plan.basis` | `moved` / `improved` | 桶大小按哪个阶段的开销算 |
| `plan.hysa` / `ret` | 数字 | 现金年利率 %、投资预期年化 % |
| `plan.foreignCounts` / `rothPrior` | 布尔 | 非美元存款是否计入应急金、是否补存上年 Roth IRA |
| `plan.end` | 月份 | 推演终点 |
| `initial` | 对象 | 起点余额与日期，字段同 3.2 |

### 3.2 月底记录

| 字段 | 含义 |
| --- | --- |
| `date` | 记录日期 |
| `checking` | 支票账户 |
| `brokerageCash` | 券商账户里的现金 |
| `hysa` | 高息储蓄 |
| `roth` / `rothPrin` | Roth IRA 总余额 / 累计存入本金 |
| `rothThisYear` / `rothPriorYear` | 本年、上年额度已存金额 |
| `brokerage` | 券商账户投资部分 |
| `k401` / `hsa` | 401(k)、HSA |
| `loan` | 债务剩余 |
| `foreign` | 非美元存款折美元 |
| `moved` | 是否已搬家 |

### 3.3 逐月输出

每行包含：`key` 月份、`stage`、`moved`、`flows`（`pay`、`bonus`、`refund`、`exp`、`carMin`、`carExtra`、`carFromSavings`、`toCash`、`fromCash`、`rothPrior`、`rothCur`、`brokerage`、`k401`、`hsa`、`loanInt`、`cashInt`）、`bal`（`checking`、`cash`、`rothCash`、`rothInv`、`brokerage`、`k401`、`hsa`、`loan`、`foreign`）、`rothUsed`（按纳税年度的已存额）、`rothPrin`、`liquid`、`net`、`notes`、`short`（支票透支标记）。

单页、中文；一个"选中月份"状态驱动待办、水桶、两张图和明细表联动。要求：高度可视化、可交互，用户不需要编辑表格。

## 6. 已知近似与局限

- 最根本的局限：目标（一笔债务、两个应急桶、Roth IRA、券商）写死在代码里；新引擎按 PRD 第 7 节改为配置驱动。测试向量依然有效，只是要用新配置格式表达同一组规则
- 税表和额度用 2026 年数值，不做通胀调整；只支持加州单身申报；加州税档和 SDI 费率为近似值
- 联邦预扣用简化年化法，不是 IRS Pub 15-T 的精确表；不考虑 W-4 设置；不处理 dual-status
- Roth IRA 收入上限未建模；401(k) 只检查员工额度，不检查 415(c) 总额
- 假设雇主对 variable 也按比例扣 401(k)
- HSA 不用 last-month rule；雇主 HSA 存入按 0 计；vesting 未建模
- 投资回报按固定年化复利，不模拟波动
- 只有一笔债务；`exp` 的类别是固定的九项
- 发薪日用本地时区构造日期；移植时统一用不带时区的日期类型
